# Логика раздела подбора

Экран `/navigator` — единственный экран подбора. Рабочий код: `app.py`, `navigator_api.py`,
`registry/rates.py`, `registry/geo.py`, `templates/navigator.html`. Макет заказчика —
`navigator/navigator.html`: пакет `navigator/` приложением не подключён (ни mount, ни роута,
ни ссылки), `/navigator` читает `templates/navigator.html` (`app.py:373-375`).

## 1. Как есть

### 1.1 GET /api/navigator — весь контракт

Роут `app.py:378-397`, query `active_only: bool = True`, авторизация — общий HTTP Basic
(`verify_creds`, `app.py:191-207`), ролей нет. Тело: `asyncio.to_thread(_build)` →
`registry_db.connect()` → `navigator_api.build_payload(conn, active_only)` (`app.py:392-396`).
Ответ — `JSONResponse` целиком: пагинации, серверной сортировки и фильтрации нет.

Базовый SQL (`navigator_api.py:718-730`): `SELECT p.*, r.raw_text, r.source_name, r.source_url,
r.parse_status, r.received_at, r.first_seen_at AS request_first_seen_at, k.photos_url,
k.photos AS kb_photos, k.project AS kb_project, k.linked_at FROM positions p JOIN requests r
ON r.request_id = p.last_request_id LEFT JOIN position_kb k ON k.position_id = p.position_id
[WHERE p.is_active = 1] ORDER BY p.last_seen_at DESC, p.position_id`. Правила ставок читаются один
раз на весь ответ (`rates.load_rules`, `navigator_api.py:736`) и передаются в каждую строку.

### 1.2 Состав строки позиции

`position_row(row, now, rules)` — `navigator_api.py:348-436`. Принцип «ничего не додумываем»:
NULL превращается в `None`/`"na"`, а не в 0 (`_b` — `:109-113`).

- **Идентификация и источник**: `id`, `ext` (last_request_id), `src` (из `SOURCE_TITLES`), `srcKey`,
  `seen` («сегодня 14:20» / «вчера» / «3 августа», `fmt_seen` — `:129-146`), `seenAt` (ISO).
- **Контрагент и ставка**: `cp`, `cpAlias` — **всегда `""`** (`:383`), `cpType` (vacancy_category),
  `obj`, `client` = `rates.client_key(counterparty, object_name)`, `rec` = `rates.resolve` (`:363-366`).
- **География**: `city`/`region` через `geo.normalize_city`/`normalize_region`, `district` = регион,
  если он не совпадает с городом (`:350-352`), `addr`.
- **Деньги и график**: `rate`, `hourly`, `unit` = `"смена"`, `net` = `""`, `sched`, `schedKind`
  (work_pattern), `hours`, `shiftType` (day→дневная, night→ночная, mixed→дневная и ночная, `:229-230`),
  `minShifts`, `workFormat`.
- **Потребность и кандидат**: `m`/`w`/`c`/`needTotal`, `gender` (`:187-201`), `ageFrom`/`ageTo`,
  `cits` (`parse_citizenship`, карта РФ/РБ/КЗ/КРГ/ЕАЭС/СНГ/УЗБ/ТДЖ/АРМ, `:151-184`), `citsRaw`,
  `req`, `duties`, `advantages`, `risks`.
- **Проверки**: `med` (no/need/arranged/na, `:218-226`), `medPayer`, `sb` (none/part/full/na,
  `:204-215`), `sbRaw`, `test` — **всегда `"na"`** (`:423`), `tsd`.
- **Блоки**: `house` (`:235-259`) — `st` = na/no/yes, `cost` = free/deduct/paid/na, `type`; `per`,
  `linen`, `transfer` реестром не хранятся. `meals` (`:262-278`) — `st` = na/no/free/deduct/paid/yes,
  `times`, `note`. `travel` (`:281-298`) — `st` = na/no/yes, `full` = full/part/`""`, `terms`;
  `amount`, `when`, `route` не заполняются. `pay` — **всегда `{"st":"na"}`** (`:430`). `ded`/`dedSt`
  (`:301-317`) — из `housing_deduction`, `meals_deduction`, `uniform_deduction`; `unit`, `when`,
  `refund` не заполняются. `media` (`:322-345`) — один элемент `{kind:"object_photo", url,
  vis:"public", alive:true, upd, src}` из `position_kb`, пусто при отсутствии `photos_url` или
  `kb_photos = 0`; `alive: true` — константа, проверки живости ссылок в коде нет (`:341`).

Дубли считаются только между **разными источниками**; ключ `_dupe_key` = `cp|city|prof|obj|shiftType`
в нижнем регистре (`navigator_api.py:439-453`, отсечка по `srcKey` — `:484`).

### 1.3 Что делает рабочий `templates/navigator.html`

Отдаётся файлом с диска, без Jinja-рендера (`app.py:366-375`), под Basic Auth. Одностраничное
приложение на ванильном JS без сборщика: состояние `S` (`templates/navigator.html:115-136`), данные
`DATA` (`:106-113`), полная перерисовка `render()` (`:855-880`) через `app.innerHTML = view()`.

- Загрузка: `fetch('/api/navigator', {credentials:'same-origin'})` (`:2189-2197`), состояния
  «Загружаем реестр…» / «Не удалось загрузить данные» (`:883-884`), `reloadData()` (`:1956`).
  Запись — только ставки: `POST /api/rates` (`saveRates`, `:1929-1948`, флаг `dryRun`) и
  `DELETE /api/rates/{id}` (`:1950-1954`).
- Экран подбора: `viewSearch()` (`:916`) = `viewAside()` (`:921-1036`, города + фильтры) +
  `viewMain()` (`:1038-1093`, scope-пилюли, поиск, сортировка, список).
- Прочее: `esc`/`attr` и белый список схем `safeUrl` (`:171-183`), сохранение скролла и фокуса между
  перерисовками (`:855-880`), дебаунс ввода 140 мс (`:2125-2160`), Escape по приоритету (`:2171-2185`).
  Пароль админ-вкладки `ADMIN_PASS = '1207'` и флаг в `localStorage` (`:99-100`, `authed()` `:622`) —
  визуальный рубеж поверх Basic Auth, не защита.

### 1.4 Фильтры

Вся фильтрация — на клиенте, `pass(r)` (`templates/navigator.html:547-598`). Порядок проверок: города →
ставка → тип ставки рекрутера → проживание → питание → гражданство → пол → возраст → медкнижка → СБ →
график → scope → полнотекстовый поиск.

| Контрол | Ключ `S` | Значения | Правило в `pass` |
|---|---|---|---|
| Ставка кандидата от | `rateMin` | число | `!r.rate \|\| r.rate < N` → отсев (`:550`) |
| Возраст кандидата | `ageCand` | число | `passAge` — пересечение с `ageFrom/ageTo` (`:539-545`) |
| Гражданство | `fCit` | любое / РФ / РФ + РБ / ЕАЭС | пустой `cits` отсекается всегда; `ЕАЭС` матчит ЕАЭС\|КЗ\|КРГ\|АРМ; `РФ + РБ` требует `РБ` (`:561-573`) |
| Проживание | `fHouse` | любое / есть / бесплатно / нет | `house.st`, `house.cost` (`:557-559`) |
| Питание | `fMeals` | любое / есть / бесплатно / нет | `meals.st` (`:561-563`) |
| Пол | `fGender` | любой / мужчины / женщины / пары | «мужчины»/«женщины» проходят и при `любые`; «пары» требуют `r.c` (`:574-576`) |
| Медкнижка | `fMed` | любая / не нужна / можно без неё | `r.med` (`:580-581`) |
| Проверка СБ | `fSb` | любая / нет / кроме полной | `r.sb` (`:583-584`) |
| График (в «Ещё фильтры») | `fSched` | «любой» + `DATA.schedules` | `r.schedKind !== S.fSched` (`:586`) |
| Ставка рекрутера (в «Ещё фильтры») | `fRec` | любая / задана / не задана / просрочена | `r.rec`, `r.rec.expired` (`:552-555`) |
| Поиск | `q` | строка | склейка `prof, req, cp, obj, city, district, cits, sched, src`, ё→е, все токены как подстроки (логическое И, `:591-596`) |

Определения контролов — `viewAside`: `numFilters` (`:992-995`), `selFilters` (`:997-1004`),
`moreFilters` (`:1005-1008`); кнопка «Ещё фильтры» со счётчиком активных — `:1009, 1030-1033`;
«сбросить» (`resetFilters`, `:1979`) обнуляет условия, но не города и не `q`. Ключ `S.recPct`
объявлен (`:120`), контрола и проверки в рабочем экране нет.
**Scope-пилюли** (`viewMain`, `:1043-1051`): «Все активные» (`DATA.rows.length`), «Под заявку» —
только при непустом `DATA.activeRequest`, то есть **никогда**, «С пробелами» (`issues(r).length > 0`).

### 1.5 Сортировки

`sorted(rows)` — `templates/navigator.html:600-614`, селект `:1053-1056`:

| value | Подпись | Правило |
|---|---|---|
| `rate` | Ставка кандидата ↓ | `(b.rate\|\|0) - (a.rate\|\|0)`, значение по умолчанию |
| `rec` | Ставка рекрутера ↓ | `recAmount(rec(b)) - recAmount(rec(a))`, нет ставки = 0 |
| `need` | Потребность ↓ | `needTotal` = `m + w + c*2`, откат на `needTotal` строки (`:212-215`) |
| `fresh` | Свежие ↑ | `String(b.seenAt).localeCompare(String(a.seenAt))` — по ISO-дате, убывание |
| `dist` | Ближе к городу | `dist()` до первого выбранного города; без координат позиция уезжает в конец (`1e9`) |

Города и радиус: гаверсинус `dist(a, b)` (`R = 6371`, округление до целого) — `:217-222`;
`nearNames()` (`:227-235`) берёт города `DATA.cities` с координатами, не выбранные вручную, у которых
расстояние до **любого** выбранного якоря ≤ `S.radius`. Тумблер «Соседние города» переключает
`radius` 0 ↔ 50 (`:1976`), пилюли — 25 / 50 / 100 км (`:987`). Расчёт расстояния существует **только
в браузерном JS**; в Python его нет — см. §2.4.

### 1.6 Ставка рекрутера — `registry/rates.py`

Слой мотивации в заявки не приходит и прийти не может: контрагент присылает сетку картинкой, правила
заводятся вручную через вкладку «Ставки» (`rates.py:1-22`). `RateRule` (dataclass, `rates.py:33-93`):
`source`, `client=""`, `vacancy=""`, `min_shifts=0`, `amount=0`, `note`, `payout`, `valid_from`,
`valid_to`, `id`, `created_at`, `author`. `scope_rank` (`:50-53`) = `(2 if client else 0) +
(1 if vacancy else 0)` — насколько правило конкретное; `scope_title` (`:55-61`) — «client · vacancy» /
«client» / «все объекты контрагента»; `expired(today)` (`:63-75`) — просроченное правило
**не прячется**, а помечается.

`client_key(counterparty, object_name)` (`rates.py:132-139`): `object_name` приоритетнее, иначе
`counterparty` — у Аметиста и КНК объект лежит в `object_name`, у Градуса и ЯППИ парсер кладёт
заказчика в `counterparty`.

`resolve(rules, source, client, vacancy, min_shifts, today)` (`rates.py:142-181`): 1) отбор применимых —
`rule.source == source and rule.client in ("", client) and rule.vacancy in ("", vacancy)` (`:151-156`),
пусто → `None`, то есть «ставка не задана», а не 0; 2) берётся **максимальный** `scope_rank`,
остальные отбрасываются (`:160-161`): объект+должность > объект > контрагент; 3) `ladder` — правила
с `min_shifts` по возрастанию, `flat` — первое без `min_shifts` (`:163-164`); 4) `_pick_step`
(`:184-205`) — лестницы нет → `flat`, `min_shifts` известен → последняя ступень с
`rule.min_shifts <= min_shifts`, вахта короче нижней ступени → `ladder[0]` + `stepNote = "вахта от
N смен — ниже нижней ступени"`, `min_shifts` не задан → `flat`, иначе `ladder[0]` + `stepNote =
"срок вахты в заявке не указан"`; 5) результат (`:170-181`) — `amount`, `tier`, `tiers`, `note`,
`payout`, `scope`, `byShifts`, `stepNote`, `validTo`, `expired`.

Запись: `POST /api/rates` собирает правила по стратегиям `all`/`shifts`/`clients`
(`_rate_rules_from_payload`, `app.py:455-496`), перед сохранением чистит область целиком
(`rates.clear_scope`, `app.py:432-434`), затем `rates.save_rules` (`app.py:435`); при `dryRun` в БД
ничего не пишется (`app.py:428-430`). Каждое изменение логируется в `recruiter_rate_history`
(`rates._log`, `:271-281`), история отдаётся `history(conn, limit=30)` (`navigator_api.py:659`).
Колонки под ставку в `positions` нет — всё считается на лету при сборке ответа.

## 2. Как должно быть — по макету `navigator/navigator.html`

Макет не подключён к приложению и работает на константах внутри файла (`ROWS` — 11 позиций,
`navigator/navigator.html:1117-1286`; `CITIES` — 10 городов, `:1091-1102`).

### 2.1 Полный список фильтров макета

Числовые (`navigator/navigator.html:2313-2316`): «Ставка кандидата от» (`rateMin`), «Возраст
кандидата» (`ageCand`). Основные селекты (`:2317-2324`): Гражданство (любое / РФ / РФ + РБ / ЕАЭС),
Проживание (любое / есть / бесплатно / нет), Питание (любое / есть / бесплатно / нет), Пол (любой /
мужчины / женщины / пары), Медкнижка (любая / не нужна / можно без неё), Проверка СБ (любая / нет /
кроме полной). Дополнительные, под «Ещё фильтры» (`:2325-2329`):
- **График** — фиксированный список `вахта / 5/2 / 6/1 / 2/2`; в рабочем — динамика из `DATA.schedules`;
- **Выплаты** (`fPay`) — еженедельно / 2 раза в месяц / есть аванс. **В рабочем экране такого фильтра
  нет и быть не может**: реестр не хранит периодичность выплат, `pay` всегда `{"st":"na"}` (`navigator_api.py:430`);
- **Тип ставки рекрутера** (`fRec`) — процент / фикс / не задана. В рабочем заменён на «задана /
  не задана / просрочена» (`templates/navigator.html:1007`): в макете модель `kind: percent|fixed`
  с базой расчёта (`navigator/navigator.html:1105-1114`), в реестре — сумма с лестницей по сменам.

Скрытый фильтр `recPct` есть в `_pass` макета (`:1926`), контрола нет; в рабочем от него остался
только ключ состояния.

### 2.2 Scope-пилюли макета

`scopes` — `navigator/navigator.html:2337-2344`: «Все активные», «Под заявку», «С пробелами».
«Под заявку» опирается на зашитую активную заявку: `reqTitle = 'Комплектовщик · Московская область ·
25 человек'`, `reqMeta = 'ЗАК-2026-0184 · закрыть до 25 августа · ответственный Кузнецова'`
(`:2346-2347`), отбор по регулярке `/комплектов|сборщик/i`; в рабочем экране чип рисуется только при
`DATA.activeRequest`, а бэкенд всегда отдаёт `null` — **пилюля и плашка недостижимы**. «С пробелами»
в макете сломана: `_pass` вызывает `this._gapList(r)` (`:1962`), а метод `_gapList` в файле
не определён — клик валит рендер `TypeError`; в рабочем используется `issues(r)` и всё работает
(`templates/navigator.html:588`).

### 2.3 Сортировки и мультивыбор городов

`_sorted` — `navigator/navigator.html:1972-1987`. Отличия от рабочего: `rec` ранжирует по типу ставки
(нет = 0, фикс = 1, процент = 2), затем по `value` — в рабочем просто по сумме; `fresh` сравнивает
строки «вчера 13:02» / «сегодня 12:04» лексикографически по возрастанию, то есть «старые сверху» —
в рабочем по ISO `seenAt` по убыванию.

Мультивыбор городов одинаков в макете и в рабочем экране: `sel` — массив выбранных городов, чекбоксы,
пилюли с крестиком, «сбросить», поиск по названию и региону с нормализацией ё→е, счётчик позиций
справа. Различается стартовое состояние: макет открывается с `sel: ['Москва']`
(`navigator/navigator.html:1057`), рабочий — с пустым выбором (`templates/navigator.html:117`).

### 2.4 Радиус — что есть и чего нет

И в макете, и в рабочем экране радиус считается **в браузере**: гаверсинус `_dist`
(`navigator/navigator.html:1491-1496`) и `dist` (`templates/navigator.html:217-222`); якорь — первый
выбранный город, соседи — города списка в пределах `radius` от любого якоря.
В Python расчёта расстояния нет вообще. `registry/geo.py` — только справочник: `CITY_ALIASES`
(`geo.py:18-34`, 14 соответствий написаний), `CITY_COORDS` (`geo.py:37-91`, **62 города**, точность
«до города»), `normalize_city` (`:109-129`), `normalize_region` (`:132-141`), `coords(city)` (`:144-148`).
Функций haversine, радиуса и «соседних городов» там **нет** — докстринг `geo.py:5-10` их обещает,
реализации не существует, поиск по репозиторию даёт совпадения только в комментариях. Координаты
уезжают на фронт как `lat`/`lon` в `cities_block` (`navigator_api.py:667-686`); нет координат —
приходит `None`, город радиусом не подхватывается и в сортировке `dist` уезжает в конец. Следствие:
радиус работает только по 62 городам справочника, остальные города реестра в него не попадают.

## 4. Текст кандидату

## Требует согласования

1. **Радиус на сервере.** Отбор соседних городов живёт в браузере и ограничен 62 городами
   `CITY_COORDS`. Решить: расширять справочник вручную, подключать геокодер или переносить расчёт
   в Python/SQL. Без решения фильтр молча пропускает города без координат.
2. **Ставка рекрутера в процентах.** Макет предполагает `kind: percent` с базой расчёта и гарантийным
   периодом; в реестре этих полей нет. Решить, заводим ли `base_amount`/`guarantee_days`
   в `recruiter_rate_rules` или процентные сетки остаются вне системы.
3. **Периодичность выплат и аванс.** Фильтр «Выплаты» и карточка «Выплаты» не заработают, пока парсер
   не извлекает эти поля, а схема их не хранит. Подтвердить приоритет доработки парсера.
4. **«Активная заявка».** Сущности нет ни в схеме, ни в API. Согласовать модель заявки заказчика
   на подбор (поля, срок, ответственный) и правило сопоставления с позициями — в макете это была
   регулярка по названию должности.
5. **Проверка живости материалов.** Подпись «перепроверка каждые 6 часов» — константа разметки,
   джоба в планировщике нет. Решить, добавляем ли пятый джоб и где хранить статус ссылки.
6. **Публичный алиас контрагента.** Пока его нет, кандидату уходит `vacancy_category`. Согласовать,
   где алиас заводится и кто его подтверждает.
7. **Проблемы `format` и `unparsed`.** Виды объявлены, но не порождаются. Решить: восстанавливаем
   ветку («ставка за час и за смену в одном поле», «дату начала не распознали») или убираем их
   из `ISSUE_KINDS`.
