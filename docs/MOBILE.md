# Требования к мобильной адаптации

## Как есть

Главный экран **уже адаптирован**. `templates/navigator.html` содержит те же
медиа-запросы, что и переданный макет `navigator/navigator.html`, — правила перенесены
дословно и местами расширены.

| Экран | Шаблон | Адаптив |
|---|---|---|
| `/navigator` | `templates/navigator.html` | **есть**: `≤900px` или `≤560px` по высоте, `≤700px`, `prefers-reduced-motion` |
| `/registry` | `templates/registry.html` | **нет собственных медиа-запросов**; таблица из 15 колонок уезжает в горизонтальный скролл `.table-responsive` |
| `/registry/{id}`, `/registry/manual`, `/registry/dictionaries`, `/vacancies` | — | **нет собственных медиа-запросов** вообще |

То есть работа осталась ровно на административных экранах на Bootstrap.

## Что реализовано на `/navigator`

### Брейкпоинт 1: `≤900px по ширине ИЛИ ≤560px по высоте`

Второе условие не менее важно первого: под него попадает телефон в альбомной ориентации,
где ширины хватает, а высоты нет.

- шапка перестаёт быть липкой: `.navHeader { position: static }`;
- колонки перестают быть панелями во всю высоту: `.navAside`, `.navMain` получают
  `position: static`, `height: auto`, `min-height: 0`, `overflow: visible`;
- внутренние прокрутки отключаются — скроллит страница целиком, иначе на телефоне
  получается вложенный скролл, из которого пользователь не выбирается;
- исключение: список городов сохраняет собственную прокрутку `max-height: 260px`.

### Брейкпоинт 2: `≤700px`

- **тач-таргеты**: кнопки, селекты и внешние ссылки — `min-height: 40px`;
- **тумблер вынесен из общего правила**: `.navSwitch` получает собственные размеры
  `58×32px` и ручку `28×28px`, иначе `min-height: 40px` отрывает ручку от трека;
- **поля ввода**: `min-height: 42px` и `font-size: 16px` — шрифт именно 16px, иначе
  iOS Safari зумит страницу при фокусе;
- **модальные окна превращаются в нижний лист**: `align-items: end`, отступ `12px`,
  карточка `max-height: calc(100dvh - 24px)`, внутренний `padding: 18px`. Единица `dvh`,
  а не `vh` — адресная строка мобильного браузера иначе обрезает низ;
- футер модалки липнет к низу карточки, чтобы экранная клавиатура его не перекрывала.

### Сквозное

`@media (prefers-reduced-motion: reduce)` глушит все анимации и переходы.

## Что осталось сделать

1. **Адаптив административных экранов.** Пять Bootstrap-шаблонов без единого
   собственного медиа-запроса. Минимум — те же два брейкпоинта и правило 16px в полях.
2. **Таблица реестра на телефоне.** `/registry` — 15 колонок. Горизонтальный скролл
   неприемлем как основной способ работы. Варианты (решение за заказчиком, см.
   [OPEN-QUESTIONS.md](OPEN-QUESTIONS.md)):
   - на `≤700px` таблица превращается в список карточек: ID, должность, город, ставка,
     потребность, статус — остальное в раскрытии;
   - таблица остаётся, но с выбором видимых колонок и залипающей первой колонкой.
   По умолчанию принимается первый вариант — он совпадает с логикой подбора, где список
   позиций всегда карточки.
3. **Запрет горизонтальной прокрутки везде.** Корень — `overflow-x: hidden`; длинные URL,
   адреса и названия объектов ломаются по словам; сетки на `auto-fit / minmax`
   схлопываются в одну колонку при 320px.
4. **Тёмная тема на административных экранах.** `data-bs-theme` не выставляется,
   `prefers-color-scheme` не обрабатывается: переход с тёмного подбора на белый реестр
   бьёт по глазам.
5. **Состояния загрузки.** Скелетонов нет нигде; на медленной мобильной сети экран
   выглядит сломанным.

## Чек-лист приёмки

Для каждого экрана:

- [ ] 320px, 375px, 414px, 768px, 1024px, 1440px — вёрстка не ломается;
- [ ] телефон в альбомной ориентации (высота ≤560px) — контент доступен без вложенного
      скролла;
- [ ] нет горизонтального скролла;
- [ ] фокус в любом поле не вызывает зум на iOS;
- [ ] модалка открывается снизу, кнопки видны при открытой клавиатуре;
- [ ] интерактивные элементы не меньше 40×40px, кроме тумблеров с собственными размерами;
- [ ] длинный адрес объекта и длинный URL материала не выталкивают вёрстку;
- [ ] `prefers-reduced-motion` выключает анимации.

Автотестов вёрстки в проекте нет. Дымовой прогон `smoke_navigator.js` проверяет логику
экрана без браузера и вёрстку не покрывает — скриншотные тесты заведены задачей `QA-*`.

Задачи — раздел «Мобильная адаптация» в [../DEVELOPER_TASKS.md](../DEVELOPER_TASKS.md).
