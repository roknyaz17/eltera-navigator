# Известные ограничения и спорные места

Что сделано временно, что работает не так, как ожидается при чтении документации,
и где нет однозначно правильного решения.

Сводка «есть / нет» — [AS-IS-VS-TO-BE.md](AS-IS-VS-TO-BE.md). Вопросы, требующие ответа
заказчика — [OPEN-QUESTIONS.md](OPEN-QUESTIONS.md).

## 1. Два независимых понятия «контрагент»

В коде это два разных объекта, называемых одним словом:

- `positions.counterparty` — заказчик, как его назвал источник, приведённый
  по справочнику;
- карточка «контрагента» в админ-части подбора, которая на самом деле собирается
  **по источнику** (`srcKey`), а не по заказчику.

Плюс `client_key()` в `registry/rates.py`, где для правил ставки приоритет отдан
`object_name`, а `counterparty` используется только если объекта нет: у Аметиста и КНК
заказчик лежит в названии объекта, у Градуса и ЯППИ — в контрагенте.

Итог: три разных ответа на вопрос «кто заказчик». Пока сущности `counterparties` нет,
свести их негде.

## 2. Два независимых списка обязательных полей

`REQUIRED_FIELDS` в `navigator_api.py` (шесть полей, для пробелов в подборе) против
`KEY_FIELDS` в `registry/queries.py` (шесть полей, для фильтра «есть пробелы» в реестре).
Пересечение — три поля. Один и тот же пробел считается по-разному на двух экранах,
и это выглядит как ошибка данных. Подробнее — [VALIDATION.md](VALIDATION.md).

## 3. Миграции

Схема накатывается автоматически при первом обращении к базе: `PRAGMA user_version`
сверяется с длиной `MIGRATIONS`, недостающие элементы исполняются подряд. Отдельной
команды нет.

Практические следствия:

- миграция выполнится в момент первого HTTP-запроса после деплоя — **до** всякой
  резервной копии;
- DDL таблицы `positions` внутри миграции v1 собирается из списков полей
  `registry/models.py`. Текст v1 меняется вместе с `models.py`, но на существующей базе
  не выполняется повторно. Добавили поле — на новой базе колонка есть, на боевой нет.
  Любое изменение набора полей обязано идти **новой** миграцией с `ALTER TABLE`;
- откатов нет: SQLite не умеет `DROP COLUMN` в старых сборках, обратных скриптов
  в проекте нет. Единственный способ отката — восстановление из копии, которую никто
  не делает автоматически.

## 4. Конфигурация живёт в коде

- идентификаторы Google-таблиц — константы в `pipeline.py`; добавление контрагента
  требует правки кода и релиза;
- путь к `credentials.json` — строка в коде;
- расписание прогонов — словарь `JOBS` в `app.py`, **и продублировано** в двух местах
  `navigator_api.py` для показа на экране: три источника правды для одного расписания;
- обязательные поля — две константы (см. пункт 2);
- значения по умолчанию `REGISTRY_DB_PATH` и `REGISTRY_ID_PREFIX` читаются на импорте
  модуля и в рантайме не переопределяются.

## 5. Хрупкие места действующего кода

| Место | Что не так | Чем грозит |
|---|---|---|
| Telethon | нет `try/except` вокруг сетевых вызовов | `FloodWaitError` или обрыв связи роняет прогон источника |
| Telegram | сообщение без текста отбрасывается на входе | заявка, присланная фото или файлом, теряется молча |
| Telegram | альбомы не склеиваются | часть многосоставного поста исчезает |
| Seatable | `accessToken` выковыривается регулярным выражением из HTML страницы | смена вёрстки Seatable ломает источник без внятной ошибки |
| Google Sheets | выгрузка с `value_input_option="USER_ENTERED"` | текст может быть интерпретирован таблицей как формула или дата |
| Планировщик | внутри процесса приложения, флага отключения нет | второй инстанс задваивает прогоны и перезапись витрины; перезапуск в момент прогона обрывает его без следа |
| LLM | нет ограничителя числа вызовов за прогон | нет предохранителя от дорогого прогона на большом снимке |
| `POST /api/rates` | тело принимается сырым `dict`, без Pydantic-модели | нечисловая сумма даёт 500 вместо понятной ошибки |
| `POST /trigger`, `/run` | задача уходит в фон, сразу отвечают «started» | ни статуса, ни защиты от параллельного запуска |
| `os.environ[...]` без значений по умолчанию | `KeyError` прилетает в середине прогона | падение через минуты после старта, а не при запуске |
| `/metrics` | ходит в SQLite на каждый scrape, ошибки глушатся | нагрузка и молчаливые сбои сбора |
| `search_index` | не чистится при деактивации и удалении позиции | индекс растёт и отдаёт погашенное |
| `position_history` | правки менеджера туда не пишутся, автора нет | историю ручных изменений восстановить нельзя |

## 6. Безопасность

- одна общая пара HTTP Basic на всё приложение, пароль в открытом виде в окружении;
- ролей нет: рекрутер видит справочники, ручной ввод, прогоны и правила ставок;
- `/health`, `/metrics`, `/jobs`, `/static`, `/docs`, `/openapi.json` открыты
  **без авторизации** — проверено на рабочем сервере; наружу уходят статистика
  по источникам, потребность, средние ставки и полная карта роутов;
- при пустых `WEB_USER`/`WEB_PASSWORD` отдаётся 500 вместо 401;
- `TELEGRAM_SESSION` — полноценный доступ к живому Telegram-аккаунту, а не токен бота;
- публичной проекции нет: `/api/navigator` отдаёт всё сразу, включая ставку рекрутера
  и внутренние обозначения; единственный барьер — клиентский `scrub()` в шаблоне,
  то есть последний, а не первый.

## 7. Интерфейс

- **две несовместимые фронт-системы**: `/navigator` — своя тёмная тема с токенами
  и liquid-glass, административные экраны — голый Bootstrap, светлый. Общего `base.html`,
  партиалов и общего CSS нет: каждый шаблон дублирует `<head>` и стили;
- мобильная адаптация есть только у подбора; пять административных шаблонов —
  без единого собственного медиа-запроса;
- модальных окон в административных шаблонах нет (кроме служебной модалки сверки);
- состояний загрузки и скелетонов нет нигде;
- доступность минимальна: `role="dialog"` и `aria-*` встречаются точечно;
- при недоступности API экран подбора не имеет внятного состояния ошибки.

## 8. Переданный макет `navigator/`

Это эталон интерфейса, но **не исходник для копирования**.

- формат `x-dc`: документ исполняется рантаймом `navigator/support.js` — сторонним
  мини-фреймворком дизайн-инструмента, который грузит React 18 и Babel с `unpkg.com`,
  компилирует шаблон через `eval` и держит мост к редактору. В продакшн его тащить нельзя;
- **без интернета макет не открывается**;
- авторизация демонстрационная: единая учётная запись в `localStorage`, логин, пароль
  и пароль администратора захардкожены в клиентском коде;
- `navigator.html` не проверяет сессию вовсе — прямая ссылка открывает экран без входа;
- `eltera/account.js` ссылается на файлы `Навигатор.dc.html`, `Портал сотрудника.dc.html`
  и `CRM.dc.html`, которых в пакете нет: переключатель продуктов ведёт в никуда;
- ссылки на материалы — заглушки `disk.example.ru`;
- `navigator/.env.example` описывает несуществующий Flask-проект (см.
  [AS-IS-VS-TO-BE.md](AS-IS-VS-TO-BE.md), раздел 6);
- фоновое видео `navigator/assets/background-loop.mp4` побайтово совпадает с уже
  закоммиченным `static/media/navigator-bg.mp4` — это одна и та же дорожка по двум путям.

## 9. Спорные места

Однозначно правильного решения нет — нужен выбор, он зафиксирован
в [OPEN-QUESTIONS.md](OPEN-QUESTIONS.md).

- **Два счётчика с похожими названиями.** Пробелы в подборе и очередь исключений
  в админке считают разное; названия обязаны различаться, иначе цифры не сойдутся.
- **Скоуп «Под заявку».** Разметка есть, `activeRequest` всегда пуст: сущности «заказ
  на подбор» нет ни в схеме, ни в API. Либо заводить, либо убирать из интерфейса.
- **Виды проблем `format`, `unparsed`, `source`** объявлены, но не порождаются ни одной
  веткой кода. Либо реализовать, либо убрать из разметки.
- **Радиус и мультивыбор городов** считаются в браузере; на сервере есть только
  координаты 62 городов и никакой функции расстояния. Перенос на сервер меняет контракт
  API.
- **Слияние дублей.** Правил автоматического слияния нет и, вероятно, не должно быть:
  решение принимает человек. Но при десятках дублей это узкое место.
- **Легаси-контур.** `REGISTRY_ENABLED=0` переключает систему на прежний путь через кеш
  Google Sheets и тянет за собой второй набор кода. Пока он поддерживается, каждая задача
  делается дважды.

## 10. Эксплуатация

- резервного копирования базы нет ни в коде, ни в compose — только рекомендация делать
  копию перед миграцией;
- журнала прогонов (`sync_runs`) не существует: что именно сделал ночной прогон,
  восстанавливается только по логам;
- логи ротируются `loguru` помесячно, stdout контейнеров ограничен 20 МБ × 3 файла;
- пароль Grafana по умолчанию — `admin`;
- тестов, покрывающих HTTP-слой, конфигурацию, миграции, Telegram-транспорт и фронтенд,
  нет; `smoke_navigator.js` требует заранее сохранённого ответа API и вёрстку не проверяет.
